Debugging Interview -- Collaboration ORIG

It is becoming more common to evaluate a candidate's debugging skills during the interview process.  Interviewers will want to see your skill in the following areas.

  • Technical - knowledge of the language
  • Troubleshooting - systematic approach to finding and fixing issues
  • Communication - how well you communicate your thought process during the debugging task (ask for clarification where needed, handle the pressure of being observed, respond to feedback, interact with your potential future colleagues)

During this exercise, you should do the following.

  • Ask for clarification when needed.
  • Communicate your thought process and explain what you are trying.
  • Identify edge cases, if any, and test your code after you fix it.
  • Speak clearly and make eye contact, being sure to explain things at a level all will understand.
  • Be prepared for interruptions when observers have questions.
  • Stay calm.  It's natural to feel nervous.  Take deep breaths and stay focused on the task.

Set Up (5 minutes)

Coordinate with classmates to create groups of 3-5 students.  Decide who will debug first.  Set up PyCharm (or an alternative environment) where you can all see the debugger's screen.

  • Debugger: works on debugging code, shares what they're thinking/trying
  • Observers: observe and may provide guidance/feedback

Set up the environment.  Here's how you could use PyCharm.

  1. The Debugger starts PyCharm, clicks the Code with Me icon in the top right corner, selects Edit if desired, and clicks the Start Session button.  After the session starts, the Debugger clicks Copy Link and sends it to the Observers via email, Zoom chat, etc.
  2. The Observers click the link sent by the Debugger and specifies a name.
  3. The Debugger allows the specified Observers access to the code.

Debug - Syntax Error (20-30 minutes)

Each person should take a turn debugging code that has a syntax error, meaning Python will not be able to interpret the code.  Instead it will report an error.  When the next person is ready, ask your professor for a new code and enter it into the Buggy Code Retriever.  

Debug - Logic Error (20-30 minutes)

Each person should take a turn debugging code that has a logic error, meaning the code produces output, but it's not correct.  When the next person is ready, ask your professor for a new code and enter it into the Buggy Code Retriever.  

Reflect and Discuss

  • What did you learn from being the Debugger?
  • What did you learn from being the Observer?
  • Discuss any challenges and how you overcame them.
