Make a Plan

There are several planning methodologies we might employ before we dive into writing code.  The strategies explored below help us make a plan, so our process is more efficient and organized.

IPO Chart - Celsius to Fahrenheit 

In an IPO chart we list the input(s), output(s), and processes needed to solve a programming task.  Say you want to write a program that can retrieve a temperature, F, in Fahrenheit, convert it to Celsius using the formula C = (F – 32) * 5/9, and display the result.  What are the inputs, outputs, and processes involved?  Drag the items on the right and drop them onto the proper categories on the left.

Day or Night Flowchart

You can use a flowchart to map the flow of your code before you write it.  Say you want to write a program that will continue asking the user to enter D or N until they enter either d, D, n, or N.  Once they've entered one of these values, you want to display "It is light outside," if they enter either d or D.  Otherwise, you want to display, "It is dark outside."  Drag the items on the right to the appropriate places in the flowchart on the left to create a program flow which describes code that could yield one possible solution.

The Game of NIM

Nim is a mathematical strategy game, which dates back to 16th century China. The game consists of two players taking turns removing objects.  The player who removes the last object wins.  Write a program which implements Nim based on the requirements below.  To help you understand the game better, you can try playing it.

NIM Program Requirments
  • Output a welcome when the game starts and a description of how to play.
  • Start with 11 sticks (use the pipe symbol | to show how many sticks remain).
  • Display the current number of sticks and prompt Player 1 for the number of sticks to remove.
  • On a player’s turn they may remove 1, 2, or 3 sticks from the pile.
  • Players alternate.
  • Verify the player entered an integer, and if not, clean up the buffer.
  • Verify the move is legal (1, 2, or 3) and that there are at least that many sticks remaining.
  • Your program should not duplicate code. Use the same code for Player1 and Player2. The only difference is that you should indicate whose turn is next (Player1 or Player2).
  • Check to see if the game is over and who won by removing the last stick. Report who won.

Below is an example run.

***** WELCOME TO NIM! *****

Each player will take turns removing
1, 2, or 3 sticks from the initial 11.
The player who removes the last stick wins!

Player 1, it's your turn!
Here are the sticks remaining: |||||||||||
How many would you like to remove? 4
Invalid move. Try again: 0
Invalid move. Try again: 3

Player 2, it's your turn!
Here are the sticks remaining: ||||||||
How many would you like to remove? 3

Player 1, it's your turn!
Here are the sticks remaining: |||||
How many would you like to remove? 3

Player 2, it's your turn!
Here are the sticks remaining: ||
How many would you like to remove? 3
Can not take more sticks than remain. Try again: 2

Congratulations Player 2, you win!


This is the largest program you've written so far.  It would be wise to at least write some pseudocode before you begin.  Sketch out an outline of what steps you'll take and how control will flow in your program.  After you've written your pseudocode, click Pseudocode for a Solution below, and compare it to yours.

HINT:  Click here to see pseudocode for one possible solution.  (Remember, there are many ways to do a thing.) 
Initialize variables:
numSticks starts at 11
player starts at 1
playing starts at true
  
Display instructions
  
While playing is true do the following:
  Tell current player it's their turn
  Show them how many sticks are remaining (use pipes)
  Ask how many they'd like to remove
  Get their answer and call it move
  
  Validate their move:
  While any of the following are true: 
    move is less than 1
    move is greater than 3
    move is greater than number of sticks
  
    if move is less than 4, but greater than numSticks,
      tell them they cannot remove more sticks than remain
    Otherwise,
      tell them their move is invalid
    
    Ask them to try entering their move again
    Get a new move
  
  Subtract move from numSticks
  
  if numSticks is zero
    Tell current player they won
    Set playing to false
  
  if player is 1, set player to 2
  else, set player to 1
