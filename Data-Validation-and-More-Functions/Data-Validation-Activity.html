Must Validate

When we get data from the user, we must check it before using it.  We need to make sure they've given us what we requested, and that they're not trying to hack our system.  If we ask for a number, they should not give us a letter or a string, etc.  But we can't count on this, so we need to validate what they give us before using it.

Get a Positive Integer 

The program below asks for a positive integer and then displays it.  As long as the user enters an integer, it appears to work.  Give it a try.

value = int(input("Enter a positive integer: "))
if value <= 0:
  print("Invalid number, try again.")
  value = int(input("Enter a positive integer: "))
print(f'Your number is {value}.')

Test the code above with the following inputs.

  • Enter -5, then enter 4.  What does it report for your number?
  • Enter 0, then enter 2.  What does it report for your number
  • Enter 7.  What does it report for your number?
Flag VALInt (5 pts)

Put the answers to the questions above together, separated by pipes to build the flag.  For example, if the answers were a, b, c, d, then enter a|b|c|d to get the flag.  The pipe is above the return/enter key on standard keyboards.


Now test the code above with these inputs.

  • Enter 3.1.
  • Enter the letter c.
  • Enter the string sterling.

In all three cases, you get a runtime error, which likely says something about an invalid literal for int(), because int() is being asked to covert the user's input to an integer.  It doesn't know how to convert 3.1, c, and sterling to integers.  We want to catch this runtime error before it can happen.

We can validate user input and handle a bad entry, like when we ask for a number and get something nonnumeric, by using a try-except pair as follows.

try:
  value = int(input("Enter a positive integer: "))
  if value <= 0:
    print("Number was out of range.")
    value = int(input("Enter a positive integer: "))

except ValueError:
  print("That was not a number.")
  value = int(input("Enter a positive integer: "))

print(f"Your number was {value}.")

The try block attempts to convert the user's input to an integer.  If the input cannot be converted, the rest of the try block is skipped.  Instead, a ValueError exception is raised, and the except block for ValueError is executed.  It reports that the value entered was not a number and gives the user another chance to enter a value.

Test the code above with these inputs.

  • Enter -5, then enter 2.  What does it report for your number?
  • Enter 3.1, then enter 4.  What does it report for your number?
  • Enter the letter c, then enter 7.  What does it report for your number?
  • Enter the string sterling, then enter 9.  What does it report for your number?
Flag VALNonNum (5 pts)

Put the answers to the questions above together, separated by pipes to build the flag.

Flag VALErrType (5 pts)

For each of the initial inputs in the last challenge, -5, 3.1, c, and sterling, an error message is reported.  If the message was "Number was out of range," record an o.  If the message was "That was not a number," record an n.  Put the n's and o's together, separated by pipes to build the flag.  For example, if "Number was out of range" is reported for -5 and 3.1, and "That was not a number" is reported for c and sterling, then enter o|o|n|n for the flag.

Raise Your Own Exception

We saw above that the Python interpreter can raise an exception, for example, when a number is requested but something other than a number is entered or when the number entered is out of range.  There are many other standard exceptions built into Python.  You can raise these built in exceptions yourself and/or raise your own custom exceptions. 

You should anticipate when exceptions might get raised and handle them elegantly rather than just letting your code crash in a runtime error.  They can be handled by any function in the current call stack. 

Consider this code, where four functions, A, B, C, and D are defined.  After all the function definitions are read in and stored for later use, function A gets called.  A calls B, B calls C, and C calls D.  As its last action each function prints that it is done.

def A():
  B()
  print("done with A")
  
def B():
  C()
  print("done with B")
  
def C():
  D()
  print("done with C")
  
def D():
  print("done with D")

A()  # <-- first line to execute

Now let's imagine something goes wrong in D and we raise an exception.  The code below will experience the custom exception we raise in D and look for a way to handle it.  When it doesn't find a way in D, it looks in C, then B, then A.  Because it doesn't find a way to handle it anywhere, the code stops abruptly and crashes inelegantly.  It doesn't report that it is done with any of the functions.  It DOES report our custom exception message.

def A():
  B()
  print("done with A")
  
def B():
  C()
  print("done with B")
  
def C():
  D()
  print("done with C")
  
def D():
  raise Exception("something went wrong")
  print("done with D")
  
A()  # <-- first line to execute

We can handle the exception in D directly with a try-except block as follows.  In this case, the program ends elegantly and reports that it is done with all functions.

def A():
  B()
  print("done with A")
  
def B():
  C()
  print("done with B")
  
def C():
  D()
  print("done with C")
  
def D():
  try:
    raise Exception("something went wrong")
  except Exception:
    print("handled exception")
  print("done with D")
  
A()  # <-- first line to execute

If we handle the exception in B instead, then when the exception is raised in D, the interpreter can't find a way to handle it there, so it falls back to C, the function which called D. C also doesn't provide a means of handling the exception, so it falls back to B, the function which called C. It DOES find a way to handle the exception in B, after which it completes the rest of the statements in B, returns to A, and completes the rest of the statements in A. 

def A():
  B()
  print("done with A")
  
def B():
  try:
    C()
  except Exception:
    print("handled exception")
  print("done with B")
  
def C():
  D()
  print("done with C")
  
def D():
  raise Exception("something went wrong")
  print("done with D")

A()  # <-- first line to execute
Flag VALNotDone (5 pts)
