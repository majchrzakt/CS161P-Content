Debug Function

We've learned about functions and explored validating user input.  The function below uses an alternative approach, regular expression matching, to check user input.  It also demonstrates how you might use default parameters in the calcArea function, in case calcArea is called with no arguments. 

The program should ask the user for a length and a width, validate their input, then calculate and report the area.  It also should report the area for the default parameters.  The code has one or more errors.  See if you can find them.

import re

# Calculate area
def calcArea(len=7.0, wid=3.0):
  area = len * wid

# Get a number from the user (may contain a decimal portion)
# Demonstrates using re (regular expressions) to validate input
# NO errors here
def getFloat(msg):
  pattern = re.compile(r'^[-+]?[0-9]*\.?[0-9]+$')  # matches a float
  badInput = True
  value = 0.0
  print(msg, end="")
  while badInput:
    inStr = input()
    # Check if value is a float (i.e., matches the pattern)
    if pattern.match(inStr):
      value = float(inStr)  # convert the string to a float
      badInput = False
    else:
      print("Invalid input. Please try again: ", end="")
  return value

def main():
  length = getFloat("Please enter a length: ")
  width = getFloat("Please enter a width: ")
  calcArea(length, width)
  print(f"The area for length={length} and width={width} is {area:.1f}.\n")

  # Demonstrates the use of default parameters -- NO errors here
  print(f"The default area is {calcArea():.1f}.\n")

if __name__ == "__main__":
  main()

Testing

Drivers and stubs provide a mechanism for testing our code as we build it.  We used them in the previous set of challenges, where main called the function we were testing.  For example, look back at getWinner.  It called getWinner nine times to test the function's behavior for different possible combinations of inputs.  

On a larger scale, and to test our code systematically during the development phase, we can have main (our driver) completely built, with each function initially being a stub.  A stub for a function returns a hard coded reasonable value for what the function is specified to return.  For example, if a function will retrieve a value between 1 and 100 from the user and return that value to the calling function when it's fully coded, then you could hard code the stub version of the function to return say 17 for now.  

If a function is not supposed to return a value, then you could have the stub output a message like, "in <insert function name>."  Alternatively, say the function is supposed to display instructions.  For now, it's stub version could just output "display instructions."  Later, when you're ready to write the code for the function, you can have it display complete and specific instructions.

Separate Compilation

To make our code easier to maintain, read, share, and collaborate on with others, we can separate it into different files.  A common practice is to put the main function in a file called main.py.  We can put functions with similar goals in an implementation file called fileName.py.

For example, we could divide the rock, paper, scissors program into the following two files.  Initially, these files could contain the main driver and function stubs as shown.  Notice that main includes an import statement at the top, so it can bring in and use the functions defined in rps.py.

main.py

# This program simulates the game rock, paper, scissors between
# the user and the computer.
# Written by <insert your name here>
from rps import displayInstructions, getCompMove, getWinner, getMove, playAgain
def main():
  keepPlaying = True
  displayInstructions.called = False
  while keepPlaying:
    displayInstructions()
    userMove = getMove()
    compMove = getCompMove()
    getWinner(userMove, compMove)
    if not playAgain("Do you want to play again y/n? "):
      keepPlaying = False

  print("Thanks for playing!")

if __name__ == "__main__":
  main()
